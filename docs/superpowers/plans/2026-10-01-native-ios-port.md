# Native iOS Port Implementation Plan

> **For agentic workers:**
> - REQUIRED SUB-SKILL: superpowers:subagent-driven-development for Waves 1–3 (parallel worktree
>   agents) and superpowers:executing-plans for Wave 0 (orchestrator, inline).
> - Steps use checkbox (`- [ ]`) syntax.

**Goal:** Replace the Flutter app in `mobile/` with a native SwiftUI app in `ios/`. It keeps every
behaviour and restyles every element to the HIG. The Flutter app moves to `mobile_flutter_depricated/`.

**Architecture:**
- **Code:** one SwiftUI app target generated by XcodeGen with synced folders, plus a WidgetKit
  extension and a Swift Testing target.
- **Patterns:** `@Observable` view models, async/await URLSession, a lenient `JSON` value that mirrors
  the Dart `fromJson` code, and typed `NavigationStack` routes.
- **Delivery:** Wave 0 (kernel) is done inline. Waves 1–2 port the code in parallel git worktrees,
  each owning disjoint folders. Wave 3 integrates and sweeps.

**Tech Stack:**
- Swift 6.4 in Swift 6 language mode, with MainActor default isolation;
- SwiftUI on iOS 26.0+, Observation, Swift Charts, RealityKit, WidgetKit, LocalAuthentication, Security;
- Swift Testing and XCUITest;
- XcodeGen 2.46, Xcode 27.

**Spec:** `docs/superpowers/specs/2026-10-01-native-ios-port-design.md`. Read it first; this plan argues from it.

## Global Constraints

- **Target:** iOS deployment target `26.0`, iPhone only (`TARGETED_DEVICE_FAMILY 1`), portrait only.
- **Swift settings:** `SWIFT_VERSION 6.0`, `SWIFT_DEFAULT_ACTOR_ISOLATION MainActor`,
  `SWIFT_APPROACHABLE_CONCURRENCY YES`.
- **Identity and signing:**
  - bundle `dev.pkrishna.intellistockMobile`, widget `dev.pkrishna.intellistockMobile.PortfolioWidget`;
  - team `VY5CNF8734`;
  - App Group `group.dev.pkrishna.intellistock`;
  - URL scheme `intellistock`;
  - display name `Intellistock Mobile`.
- **Dependencies:** none from third parties. Apple frameworks only.
- **Keychain continuity:** service `flutter_secure_storage_service`, with these keys verbatim:
  `intellistock_token`, `intellistock_user`, `api_base_url`, `biometric_lock_enabled`, `lock_timeout`,
  `dashboard_selected_account`, `pinned_instances`.
- **App Group keys, verbatim:** `widget_api_base`, `widget_token`, `portfolio_data`, `positions_data`,
  `instances_data`, `accounts_data`, `synced_at`.
- **API parity:** every endpoint path, method, query key and body key is byte-identical to the Dart
  call site.
- **Copy:** user-visible strings stay verbatim, except where HIG title-style capitalisation applies.
  Each such change is listed in the parity checklist.
- **Liquid Glass:** only on system bars and floating controls, never on content cards.
- **No gradients anywhere.** That covers `LinearGradient`, `RadialGradient`, `AngularGradient`,
  `.gradient` fills, glows, blooms, coloured shadows and decorative backgrounds. Chart areas use a flat
  fill at 15 % opacity or less. Screens sit on the plain system grouped background. The operator
  asked for this on 2026-10-01: "remove the gradients in the new app as well and make it look more
  apple UI like". Look to Apple's Stocks, Wallet and Settings apps.

  - `SubStrategy` in `backtests` becomes `BacktestSubStrategy`.

  Helper views are `private`.
- **Folder ownership (Wave 2):** never edit `Core/`, `DesignSystem/`, `App/` or another agent's
  `Features/<X>/` folder. Request changes in the final report.
- **Branches:** never stage `AGENTS.md` or `CLAUDE.md`. Never push to `main`; it auto-deploys the
  backend and restarts the real-money instance.
- **Commits:** every commit ends with the trailers

  `Claude-Session: https://claude.ai/code/session_018r9pQCcQTaFQbERjCD6xPg`.

## Review Focus

1. **Upgrading over the Flutter build.** The native app must read the Flutter keychain items and stay
   signed in on the same server. *Test (Task 0.2):* write an item with raw `SecItemAdd` using the
   flutter attributes, then read it through `KeychainStore`.
2. **Backend numbers that arrive as `"5"`, `5`, `5.0` or `null`.** Models must coerce exactly as the
   Dart `num?`/`toString()` code does, never crash, and never show `5.0` where Dart showed `5`.
   *Test (Task 0.2):* JSON accessor matrix.
3. **A token that expires mid-session.** A 401 clears the session and returns to Login without
   stranding a screen, and an `x-refreshed-token` header persists the new token. *Test (Task 0.3):*
   `ApiClient` with a `URLProtocol` stub.
4. **Backgrounding.** Polling stops in the background and resumes on foreground. The lock engages per
   `lock_timeout` and never over the login screen. *Test (Task 1C):* `PollingLoop` pause test and the
   ported `app_lock_controller_test`.
5. **Changing the server URL in Settings.** The session is cleared and the client is rebuilt against
   the new origin, and no request goes to the old host. *Test (Task 1C):* `AppServices` rebuild test.

```swift
enum JSON: Hashable, Sendable {
  case null, bool(Bool), number(Double), string(String), array([JSON]), object([String: JSON])
  init(data: Data) throws
  init(any: Any?)
  func data() throws -> Data
  subscript(key: String) -> JSON { get }
  subscript(index: Int) -> JSON { get }
  var isNull: Bool { get }
  var string: String? { get }       // Dart x?.toString()
  var double: Double? { get }       // (x as num?)?.toDouble()
  var int: Int? { get }             // (x as num?)?.toInt()
  var bool: Bool { get }            // x == true
  var boolValue: Bool? { get }      // x as bool?
  var array: [JSON]? { get }
  var object: [String: JSON]? { get }
  var arrayValue: [JSON] { get }    // ?? const []
  var objectValue: [String: JSON] { get }
  func stringOr(_ d: String) -> String
  func doubleOr(_ d: Double) -> Double
  func intOr(_ d: Int) -> Int
}
extension JSON: ExpressibleByDictionaryLiteral, ExpressibleByArrayLiteral,
               ExpressibleByStringLiteral, ExpressibleByIntegerLiteral,
               ExpressibleByFloatLiteral, ExpressibleByBooleanLiteral, ExpressibleByNilLiteral {}

struct KeychainStore: Sendable {
  static let flutterService = "flutter_secure_storage_service"
  init(service: String = KeychainStore.flutterService)
  func read(_ key: String) -> String?
  func write(_ key: String, _ value: String) throws
  func delete(_ key: String)
}
```

- [ ] **Step 1:** Write the failing tests:
  - `JSON.number(5).string == "5"` and `JSON.number(5.5).string == "5.5"`;
  - `.int` reads `5` and `5.0` as 5, and does not read `"5"` (matching `as num?`);
  - `JSON.null.stringOr("x") == "x"`;
  - `.bool` is true only for `true`;
  - nested subscript on a missing key returns `.null`;
  - a round trip through `init(data:)` and `data()`;
  - the keychain: write, read, delete, then read returns `nil`;
  - an item added with raw `SecItemAdd` using `kSecAttrService = flutter_secure_storage_service` and
    `kSecAttrAccount = "k"` is readable through `KeychainStore.read("k")`.
- [ ] **Step 2:** Run the tests and confirm they fail to compile.
- [ ] **Step 3:** Implement `JSON`. Numbers are a `Double`. `.string` prints integers without a
  fraction and other numbers with Dart `toString` semantics. `.int` and `.double` accept only `number`,
  matching `as num?`. Sites that used `int.tryParse`/`double.tryParse` call `JSON.parseInt`/`parseDouble`
  explicitly. Then implement `KeychainStore` with `kSecClassGenericPassword`.
- [ ] **Step 4:** Run the tests and confirm they pass.
- [ ] **Step 5:** Commit: `feat(ios): lenient JSON value and flutter-compatible keychain store`.

```swift
struct ApiError: Error, LocalizedError, Equatable {
  let message: String; let statusCode: Int?
  var errorDescription: String? { message }
  static func from(status: Int?, body: Data?, transport: URLError?) -> ApiError
}

protocol ApiTokenSource: AnyObject {           // implemented by SessionStore (Wave 1)
  var token: String? { get }
  func setToken(_ token: String) async
  func clear() async
}

final class ApiClient {
  init(baseURL: String, tokens: ApiTokenSource?, session: URLSession = ApiClient.makeSession())
  func get(_ path: String, query: [String: String?] = [:]) async throws -> JSON
  func post(_ path: String, body: JSON? = nil, query: [String: String?] = [:]) async throws -> JSON
  func put(_ path: String, body: JSON? = nil) async throws -> JSON
  func patch(_ path: String, body: JSON? = nil) async throws -> JSON
  func delete(_ path: String, query: [String: String?] = [:]) async throws -> JSON
}
```

Query values are `String?`. A `nil` value omits the key, which matches Dio dropping null query params.

## Agent protocol (Waves 1–2)

Every port agent:

1. **Before reading code.** Reads the spec, then this plan's Global Constraints, Review Focus and its
   own task.
2. **Skills.** Invokes `ecc:swiftui-patterns`, `ecc:swift-concurrency-6-2`, `ecc:liquid-glass-design`
   and `apple-design`, plus `ecc:swift-protocol-di-testing` for its tests.
3. **Reading.** Reads **every** owned Dart file in full. No skimming: parity is the bar.
4. **Parity checklist.** Writes `ios/parity/<agent>.md` before porting (spec §9).
5. **Order of work.** Ports the models and logic with their tests first, then the views, restyling in
   the same pass using spec §7.
6. **Builds.** Uses its own DerivedData: `-derivedDataPath ios/build/dd-<agent>`. Runs `xcodegen
   generate` only when `project.yml` changed; Wave 2 agents never change it.
7. **Done means:**
   - every checklist item is ticked or annotated "→ native form: …";
   - `xcodebuild … build test` is green;
   - there are no warnings in owned files;
   - the work is committed on its worktree branch.
8. **Report.** Returns:
   - the branch name and commit SHAs;
   - the checklist counts;
   - every deliberate deviation;
   - any change it needs in folders it does not own.
9. **GateGuard.** When the gate blocks a new file, it presents the facts the gate asks for (callers,
   no duplicate, data shape, the operator's instruction quoted below) and retries.
