# IntelliStock MCP Server (Build D) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `backend/mcp_server/` — a separately-imaged MCP server that signs Jarvis in with its own OAuth 2.1 authorization server and exposes the IntelliStock API to it as catalog + direct tools derived at runtime from the API's OpenAPI schema.

**Architecture:** One Starlette app built by the official MCP Python SDK v2 (`Server.streamable_http_app`, stateless JSON, bearer-protected `/mcp`), plus our authorization-server routes composed from the SDK's own OAuth handlers and our login/enrollment pages. Auth state lives in a private SQLite file on the container's volume; every tool call becomes one HTTP call to the API's MCP listener (`http://api:8012`) with the service token and the acting user, and every result is redacted, wrapped as untrusted, and capped before Jarvis sees it.

**Tech Stack:** Python 3.11, mcp 2.1.1 (+ mcp-types), Starlette 1.10, uvicorn 0.54, httpx 0.28 (API client), PyJWT 2.15 (EdDSA), cryptography 50, py_webauthn 3.0.1, pyotp 2.12, jsonschema 4.26, segno (QR SVG), stdlib sqlite3; pytest 9.2 + pytest-asyncio 1.5.

**Spec:** `docs/superpowers/specs/2026-11-19-intellistock-mcp-server-design.md` §5.2 (this build), bound by `docs/superpowers/specs/2026-11-19-intellistock-mcp-contract.md` (§2 headers, §3 gate responses, §4 internal endpoints, §5 approvals, §7 environment and compose). ## Review Focus

1. **tailscale serve forwards a Host header that differs from `MCP_PUBLIC_BASE`'s netloc.** Then every request gets 421. The operator should see one log line naming the Host it received and the `MCP_EXTRA_ALLOWED_HOSTS` escape hatch, not a silent failure. Tests: Task 17 `test_unknown_host_421_and_hint_logged`, `test_extra_allowed_hosts_accepted`.
2. **The API is down or redeploying (every merge restarts it).** The server must still start; catalog tools should say the catalog is loading; calls should return a correlation id and, for writes, say a retry with the same `idempotency_key` is safe. Tests: Task 14 `test_watcher_initial_backoff_until_api_up`, Task 16 `test_api_unavailable_result`, `test_catalog_loading_message`.
3. **A path-parameter value such as `..`, `.`, `a/b` or an empty string.** httpx normalises dot segments, so `/instances/..` would silently hit a different route. Such values must be rejected or percent-encoded before any request leaves. Test: Task 4 `test_build_path_encodes_and_rejects`.
4. **Huge results, such as a whole backtest log file.** The 100 KB cap must keep the log tail (the useful end), say what it cut, and name the paging parameters. A response over 10 MB is aborted, never buffered. Tests: Task 15 `test_cap_keeps_log_tail`, Task 4 `test_oversized_response_aborted`.
5. **Two Jarvis processes refresh with the same token at the same moment.** Both must get the same successor pair, with no family revocation and no `refresh_reuse_revoked` event. Test: Task 7 `test_concurrent_rotation_same_token_both_succeed`.

## Decisions made without the operator (review these)

1. **Alerts go through the API (lead ruling; contract §4 updated).** The server has no Discord path of its own. It logs `refresh_reuse_revoked`, `lockout` and `disabled` at WARNING and POSTs them, like every auth event, to `/internal/mcp/audit-event`; the API relays those three to Discord through its existing notification path. There is no `MCP_DISCORD_WEBHOOK_URL`.
2. **The SDK's authorization-server hooks are used, but we assemble the routes ourselves.** We use the SDK's `OAuthAuthorizationServerProvider` protocol, `AuthorizationHandler`, `TokenHandler`, `ClientAuthenticator` and `MetadataHandler`, and do not call `create_auth_routes`. That lets the metadata advertise `token_endpoint_auth_methods_supported: ["none"]` (a public client) with no registration or revocation endpoint and no CORS. It also keeps the issuer byte-identical to `MCP_PUBLIC_BASE`: a spike showed that `build_metadata(AnyHttpUrl(base))` appends `/`, and the SDK client then rejects the issuer. The login step plugs in through `provider.authorize()`, which returns our `/login` URL. Dynamic registration stays off because the `/register` route is never mounted. The same spike ran the SDK client's full flow against these handlers: discovery, PKCE, `resource` sent, pre-registered client, no DCR.
3. **The Jarvis client is configured from environment variables** (`MCP_JARVIS_CLIENT_ID`, `MCP_JARVIS_REDIRECT_URI`), not stored in SQLite. There is one source of truth and no admin command to keep in sync.
4. **An unconfigured container idles.** With required variables missing it serves `/healthz` and returns 503 for everything else, rather than crash-looping. Merging this before deploy configuration exists is therefore harmless.
5. **The `mcp` service has no `env_file`.** It gets explicit variables only, so the broker, LLM and database secrets in `.env` never enter the container. A compose test pins that only `api` and `mcp` join `mcp_net`.
6. **Schema hash and polling (lead ruling; contract §4 updated).** The hash is exactly `sha256(json.dumps(paths, sort_keys=True, separators=(",", ":"), ensure_ascii=False).encode("utf-8")).hexdigest()`. A document whose published `x-mcp-schema-hash` differs from that is rejected and the previous catalog kept. `/health` and `/internal/mcp/*` on :8012 need only the service token, CIDR and listener, so the watcher polls `/health` every 60 s with no fallback.
7. **Enrollment.** Both factors are required: a passkey (user verification required) and TOTP. Re-enrolling replaces all of a user's factors and revokes that user's sessions. The TOTP QR is shown exactly once; reloading the page means restarting with the CLI. Sign-in is password plus (passkey or TOTP).
8. **Revocation is immediate.** Access tokens carry `sid` (the refresh family), and every `/mcp` request checks that the family is still active. `rotate-signing-key` invalidates every access token at once; refresh tokens keep working, so Jarvis re-mints without signing in again.
9. **`get_approval` and `list_pending_approvals` are built in** and always present, even before the schema loads. Schema-declared tools with those names are skipped.
10. **Input schemas.** Request bodies sit under one `body` property; path and query parameters sit at top level, with `additionalProperties: false`. Every API result is wrapped in the untrusted-content envelope, not only the fields that look like free text.
11. **QR codes come from `segno`**, a new pure-Python dependency with no dependencies of its own, rendered as an inline SVG data URI. There is no CDN and no JavaScript QR library.

rotate(active) inside db.tx():
  UPDATE refresh_tokens SET rotated_at=now WHERE token_hash=? AND rotated_at IS NULL

  mint successor refresh token, insert its row, access = issuer.issue(user_id, family_id)
  grace_blob = seal(derive_key(master, "refresh-grace"), json{access_token, refresh_token, exp}, aad=old token_hash)

rotate(grace): unseal -> IssuedPair(same strings, expires_in=max(0, exp-now))

purge: grace_blob=NULL where grace_until < now; delete families with abs_expires_at < now - 86400 (cascade)

- **Metadata** is built from plain strings (never `AnyHttpUrl(...)`, which appends `/`): `issuer=public_base`, `authorization_endpoint=public_base+"/authorize"`, `token_endpoint=public_base+"/token"`, `scopes_supported=["mcp"]`, `response_types_supported=["code"]`, `grant_types_supported=["authorization_code","refresh_token"]`, `token_endpoint_auth_methods_supported=["none"]`, `code_challenge_methods_supported=["S256"]`.
- **Routes:** `MetadataHandler` at `/.well-known/oauth-authorization-server` (GET); `AuthorizationHandler(provider)` at `/authorize` (GET, POST); `TokenHandler(provider, ClientAuthenticator(provider))` at `/token` (POST). Each is wrapped in `RequestBodyLimitMiddleware(request_response(handler), 16384)`. There is no `/register`, no `/revoke` and no CORS.
- **authorize** checks, in order:
  1. Server disabled → `AuthorizeError("temporarily_unavailable")`.
  2. `redirect_uri_provided_explicitly` False, or `str(redirect_uri) != jarvis_redirect_uri` → `invalid_request`.
  3. code_challenge not `^[A-Za-z0-9_-]{43}$` → `invalid_request`.
  4. `resource` missing → `invalid_request` (`"resource is required"`); `resource != resource_url` → `invalid_target`.
  5. Scopes default to `["mcp"]`.

  Then store the txn (`new_token("mcptx_")`, hashed, TTL 600 s) and return `f"{public_base}/login?txn={txn_id}"`.
- **exchange_authorization_code:** compare-and-swap `used_at`. A lost race or replay → revoke the code's `family_id` and raise `TokenError("invalid_grant")`. Otherwise `sessions.start`, record `family_id` on the code, and return `OAuthToken(access_token, "Bearer", 900, "mcp", refresh_token)`. Codes are `new_token("mcpac_")` with TTL 120 s.
- **load_refresh_token** goes through `sessions.lookup` and the client must match. **exchange_refresh_token:** disabled → `TokenError("invalid_grant", "server disabled")`; `sessions.rotate` returning None → `invalid_grant`.

**Catalog rules.**
- Skip an operation (and record `"<method> <path>: <reason>"` in `skipped`) when any of these hold:
  - its operationId is missing or not `[A-Za-z0-9_]{1,64}`, or duplicated (both copies skipped);
  - it has no `x-mcp`, or its class is not in CLASSES (so `never` is skipped defensively);
  - its method is not get/post/put/patch/delete;
  - it uses a non-local `$ref`.
- The input schema is `{"type": "object", "properties": {...}, "required": [...], "additionalProperties": False}`:
  - path params are always required;
  - query params are required per `required`;
  - header and cookie params are ignored;
  - the `application/json` request body becomes property `body`, required when `requestBody.required`.
- `$ref`s of the form `#/components/schemas/X` are inlined. A cycle becomes `{"type": "object", "description": "Recursive reference to X; send a JSON object."}`, and depth is capped at 32.
- Summary is `summary` or the first line of `description`, ≤ 200 chars; description ≤ 2000 chars. `schema_hash` is `canonical_paths_hash(doc["paths"])`.
- Search: tokens = `re.findall(r"[a-z0-9]+", query.lower())`. Score +3 per token among the operation_id's `_`-tokens, +2 if the token is in the path, +1 if in the summary or description. A zero score is dropped (an empty query matches everything). Sort by (-score, operation_id); return `(results[:limit], total_matches)`.

- `tick`: `h = health_schema_hash()`. If h is None (API down), do nothing this tick. If `current is None or h != current.schema_hash`, refresh.
- `run`: retry the initial refresh with a 1, 2, 4 … 60 s backoff until it succeeds, then loop `sleep(poll_s)` → `tick` forever, logging and swallowing exceptions.

  - a dict trims its largest list field repeatedly, keeping the tail for keys `logs` and `lines` and the head otherwise;
  - anything else becomes `{"preview": <JSON text cut to fit>}`.

  It adds `"truncated": {"original_bytes", "limit_bytes": 102400, "note": "Result exceeded 100 KB and was cut.", "trimmed": [{"path": "data.logs", "kept", "total", "kept_from": "end"|"start"}], "page_with": [...paging_params]}`.
- **Errors** (JSON text, `is_error=True`; `<cid>` is the request's correlation id):
  - 4xx: `{"error": {"status": S, "detail": D}}`, with `retry_after_s` added on 429. D is the API's `detail` (or text), redacted and sanitised, cut to 500 chars + `…`.
  - 401 replaces D with `The IntelliStock API rejected the MCP service credentials (MCP may be disabled on the API). Correlation id: <cid>.`
  - 5xx: `{"error": {"status": S, "message": "The IntelliStock API failed. Correlation id: <cid>."}}`
  - unavailable: `{"error": {"message": "The IntelliStock API could not be reached. Correlation id: <cid>.", "retry": R}}`, where R = `Safe to retry with the same idempotency_key.` for a non-read and `Safe to retry.` otherwise.
- **Pending** (not an error): `{"pending_approval": {id, summary, money_state, expires_at}, "next_step": "The operator must approve this in the IntelliStock app. Check progress with get_approval(id)."}`.

| class | read_only | destructive | idempotent | open_world |

| read, and find/describe/approvals | T | F | T | F |
| write | F | F | F | F |
| money | F | T | F | T |
| irreversible, and `call_endpoint` | F | T | F | F |

**Direct tools.**
- Name `op.tool`. Description `op.summary`, plus ` Needs operator approval when the target is live.` for money or ` Always needs operator approval.` for irreversible.
- Schema `op.input_schema`, plus a required `idempotency_key` when the class is not read.
- Skip (with a log line) when the name fails `[A-Za-z0-9_-]{1,64}`, collides with BUILTIN_TOOLS, or collides with another op's tool (both skipped).
- Keep at most `max_direct_tools` (sorted by name), warning when any are cut.

**call(), in order.**
1. Validate the tool arguments with `jsonschema.Draft202012Validator`; on failure return `tool_error` listing ≤ 5 `"<json path>: <message>"`.
2. Catalog None → `The endpoint catalog is still loading from the IntelliStock API; try again in a minute.`
3. Unknown op → `Unknown operation '<x>'. Use find_endpoints.`
4. For `call_endpoint`, validate `arguments` against `op.input_schema`.
5. Non-read without a key → `idempotency_key is required for write, money and irreversible operations. Use a new unique key per action and reuse it to retry the same action.`
6. Split the arguments into path, query and `body`, call `build_path` (PathParamError → `tool_error`), then `api.request`.
7. Map the response:
   - 202 with `pending_approval` → `pending_result`;
   - other 2xx → `success_result` (`replay` from header `x-mcp-idempotent-replay == "true"`, paging from the op);
   - ≥ 400 → `api_error_result`;
   - ApiUnavailable → `unavailable_result`.

Approvals: `get_approval` → `GET /mcp/approvals/{id}`; `list_pending_approvals` → `GET /mcp/approvals?status=pending&limit=N`. Both are reads, and their results go through `success_result`, so approval results are redacted.
